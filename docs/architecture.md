- **Classification & Data Quality (Phase 5):** Deterministic, metadata-only classification proposals (versioned rules, confidence semantics, immutable history with input fingerprints); on-demand data-quality checks (missing metadata, invalid/unsupported extensions, conflicts, duplicate candidates, stale observations, source-mapping inconsistencies, unclassified) — never reads file contents, never mutates asset fields, never selects/executed a retention policy or lifecycle action. Write runs guarded in production (ADR-0012). Frontend minimal view with loading/empty/error states and explainable evidence/warnings/conflicts.
- **Unified Review Workflow & Governance (Phase 6):** A single review queue (`GET /api/v1/retention/recommendations`) with server-side institution/review-status/recommendation/severity filters, permitted-metadata search, deterministic urgency/age sorting, and pagination; a read-only unified asset view (`GET /api/v1/governance/assets/{asset_id}`) aggregating inventory + source/scan, latest classification, quality findings, applicable policy and exact version, latest assessment and history, active holds, and append-only decisions with explicit provenance labels. Human decisions reuse the append-only `retention_decisions` table (`retain` / `request_more_information` / `approve_for_later_workflow` / `reject`), now race-safe via a unique `assessment_id` constraint (ADR-0013). Submissions carry optimistic-concurrency tokens and are rejected as stale (`409 stale_review_conflict`) or hold-blocked (`409 hold_conflict`); decisions are not execution commands and no archive/restore/move/delete is implemented.
- **Production write guards:** Retention/connector/classification writes and Phase 6 review-decision creation return 503 in `ENVIRONMENT=production` until real authN/authZ exists (ADR-0010–0013). Read-only operations remain available.
- **Identity, Authorization & Decision Supersession (Phase 7):** Server-verified identity via strict HS256 JWT bearer tokens (stdlib only) with issuer/audience/expiry/signature validation; production fails closed (503 `auth_not_configured:`) whenever the signing secret is missing or is the development placeholder, and the development sign-in provider is hard-disabled there (ADR-0014). Authorization is one `require_permission` dependency on every protected endpoint, backed by a local user directory that is authoritative over token claims; roles are viewer/reviewer/admin plus a platform administrator flag, out-of-scope resources answer 404 (no existence leak), and denied writes are audited (`authorization.denied`). Human decisions gain **supersession** (ADR-0015): a correction is a new decision linked by `supersedes_decision_id` (unique successor index, lineage/self-reference/cycle validated, effective decision derived server-side, full history preserved — no edit or delete path exists anywhere). The frontend adds sign-in/sign-out, permission-aware navigation and actions, institution scope selection, session-expired handling, and supersession/effective markers in the review history — all usability only; the backend re-authorizes every request. Migration `0011_platform_admin_default_false` corrects the unsafe `0008` platform-admin server default: it revokes ambiguous existing grants and sets future defaults to false (ADR-0017); a trusted operator must explicitly re-grant verified platform admins. Migration `0010` repairs the `classification_results` downgrade inversion and sets the supported rollback boundary at `0005` with tested safe failure below it (ADR-0016). A real identity provider (RS256/JWKS) is **not** configured or claimed: production authentication stays fail-closed until an operator sets a real secret and IdP integration is implemented and tested.
